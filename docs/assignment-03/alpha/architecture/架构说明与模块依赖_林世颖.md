- 接口路径、字段、状态值与协议方法以 `docs/assignment-03/interface-contract-v1.md` 及 `backend/contracts/` 为准，本说明不修改公共契约。
- 架构图中绿色实线表示已实现（代码落地），灰色虚线表示仅契约或尚未实现，蓝色表示公共契约层。

## 3. 当前系统实际架构

对应图件：`当前系统架构图_林世颖.drawio` / `.svg` / `.png`。

当前 main 分支的可运行部分集中在后端骨架、公共契约、Mock 与适配器、本地文档解析器及配套测试：

1. 学生端前端尚未落地，与后端之间目前只有 HTTP 契约约定，没有实际浏览器工程。
2. FastAPI 骨架提供健康检查与问答契约入口，统一处理请求校验、请求 ID、CORS 与错误信封；未注入 Agent 时返回服务未配置错误，不产生伪造回答。
3. 公共契约层由 `models.py` 与 `protocols.py` 构成，已落地的服务适配器与 Mock 均遵守其中的类型与协议边界。
4. 已落地服务包括 Mock Agent、Qwen 适配器、文档解析器与错误体系；其中 Qwen 适配器与文档解析器均只完成协议适配或本地解析，未接通真实模型调用、入库、索引与检索开放。
5. 真实 Agent、检索、数据库在线接入、入库索引、后台管理端与认证授权目前仅保留协议或接口约定，图中以虚线框标注。

## 4. 目标系统架构

对应图件：`目标系统架构图_林世颖.drawio` / `.svg` / `.png`。

Alpha 目标分层与调用方向如下：

1. 学生浏览器通过 HTTP/JSON 访问 FastAPI 后端，负责问题输入、回答与引用展示、追问交互与反馈。
2. FastAPI 后端完成请求校验、ID 管理、Agent 调用入口与错误处理，不直接编排业务规则。
3. Agent 工作流内部包含业务规则配置、Retriever 检索与 LLMClient 模型适配三个协作部分。
4. 数据资源层包括关系数据库、向量/全文检索索引与知识库资料文件；嵌入模型与检索部署方案尚未最终确定。
5. 后台管理端通过管理服务链路对接文档解析与入库索引，负责资料列表、详情、元数据维护、导入与重索引。

后端与 Agent、Agent 与检索/模型之间使用 Python 类型化接口；浏览器与后端之间使用 HTTP/JSON，内部调用不额外引入 HTTP 服务。

## 5. 模块依赖与接口对照

| 调用方 | 被调用模块 | 接口 / 协议 | 输入 → 输出 |
| --- | --- | --- | --- |
| 浏览器 | FastAPI 后端 | `GET /api/v1/health` | 无 → 健康检查响应 |
| 浏览器 | FastAPI 后端 | `POST /api/v1/ask` | `query`、`conversation_id` → `AskResponse` |
| FastAPI 后端 | Agent 工作流 | `AgentService.run()` | `AgentRequest` → `AgentResult` |
| Agent 工作流 | 检索模块 | `Retriever.retrieve()` | `RetrievalRequest` → `list[RetrievedChunk]` |
| Agent 工作流 | 模型适配 | `LLMClient.generate()` | `LLMGenerateRequest` → `LLMResult` |
| 资料处理链路 | 文档解析 | `DocumentParser.parse_document()` | 文件路径 + `DocumentMetadata` → `DocumentPackage` |
| 索引链路 | 入库索引 | `KnowledgeIndexer.index_document()` | `DocumentPackage` → `IndexResult` |
| 后台管理端 | 管理服务 | `DocumentAdminService` | 列表、详情、导入、重索引相关调用（P1，未实现） |

管理 API 契约范围（P1，均未实现）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/admin/documents` | 资料分页列表，可按状态筛选 |
| GET | `/api/v1/admin/documents/{document_id}` | 资料详情、版本与处理状态 |
| POST | `/api/v1/admin/documents` | 上传/登记资料并触发解析 |
| PATCH | `/api/v1/admin/documents/{document_id}` | 修改允许维护的元数据 |
| POST | `/api/v1/admin/documents/{document_id}/reindex` | 重新构建索引 |

状态口径：

- 问答状态 `status`：`answered`、`needs_clarification`、`insufficient_evidence`。
- 回答用途 `answer_mode`：`current_policy`、`historical`、`procedure_reference`、`insufficient_data`。
- 检索器默认只返回 `retrieval_status=enabled` 的片段；没有符合条件的证据时返回空列表，不返回 blocked 资料作为正式政策依据。
- 索引完成不自动开放检索；开放检索须满足核验条件并经明确流程确认。

## 6. 问答调用流程

对应图件：`问答调用流程图_林世颖.drawio` / `.svg` / `.png`。

1. 学生在浏览器提交问题，后端通过 `POST /api/v1/ask` 接收 `query` 与 `conversation_id`。
2. FastAPI 后端完成请求校验，生成或沿用 `request_id` 与 `conversation_id`，构造 `AgentRequest` 交给 Agent 工作流。
3. Agent 进行意图识别与信息完整性判断：信息不充分时，返回 `needs_clarification` 与 `clarifying_question`，前端展示追问并等待用户补充后再次提交。
4. 信息充分时，Agent 调用 `Retriever.retrieve()` 检索处于 `enabled` 状态的片段。
5. 检索结果中没有可用证据时，返回 `insufficient_evidence`，附带解释与 `warnings`，`citations` 为空，不伪造政策答案。
6. 存在可用证据时，Agent 调用 `LLMClient.generate()` 组织回答；模型输出不作为证据，引用只能来自检索返回并被本次回答实际采用的片段。
7. `AgentResult` 由后端包装为 `AskResponse` 返回前端；前端展示回答、引用与 warnings。

## 7. 设计约束与边界

- 各模块导入公共模型与 Protocol，不在各自模块中重复定义相同 DTO；公共字段、类型、路径、状态值与函数签名的变更须先报组长统一确认。
- 文档完成解析、入库或建立索引，不等于政策已核验，也不等于可以进入正式问答检索。
- 当前尚未完成认证授权接入，管理端 API 不能对公网暴露；前端隐藏按钮不构成权限控制。
- 模型 API Key 只从环境变量读取，不写入源码、文档、日志或 Git 历史；不向浏览器传递密钥、数据库连接串、内部堆栈或本地绝对路径。
- 浏览器不直接访问数据库或检索存储。
