# 后台管理原型

负责人：林彦翔

Figma 在线原型：https://www.figma.com/design/Wan3sZFRzZyAo8JtW3olYV/agent%E5%8E%9F%E5%9E%8B

本目录为后台管理端原型，共 17 个页面 + 5 个交互弹窗，覆盖管理概览、资料审核与发布、资料编辑、用户管理、角色权限、数据来源与索引、运行记录、反馈与审计等管理动作。截图位于 `screenshots/`，均由 Figma 可编辑画板导出。

## 本轮修改（对照第一轮评审意见）

| 评审意见 | 处理 |
|---|---|
| 一、管理概览要与最新产品规划统一 | A25 改为 PPT / 产品规划的 5 个方向：政策与事务办理、升学与就业发展、竞赛与科研信息、学院资源导航（v1.0）+ 个人成长档案（v2.0，后续迭代）；卡片数字按知识库 44 条（7 类）归并为 10 / 12 / 9 / 13，v2.0 另注 5 条预留资料 |
| 二、审核通过与正式发布区分开 | A27 保持一键操作（后台审核方即发布方），但把「发布」作为系统动作显性化：状态条区分 v2 待审核与 v1 在线，审核记录拆成「审核通过」与「发布索引 v1.4 成功」；索引失败时进入「发布失败 · 可重试」并可保留上一可用版本；A26 增加对应状态示例 |
| 二、保留原文快照、适用范围、有效期、来源链接与审核记录 | A27 全部保留，并补充版本信息 |
| 二、编辑后重新进入审核，不覆盖已发布版本 | A37 只保留 保存，保存生成 v2 待审核版本；审核通过后才替换 v1 |
| 三、运行案例改为首版核心场景 | A29 的 RUN-1024 改为「竞赛类别认定」，另两条为奖学金申请条件、保研条件 |
| 三、运行详情体现处理过程 | A30 明确 识别需求 → 检索资料 → 校验适用性 → 生成回答 四步，并列出每条候选来源的采用 / 排除 |
| 三、保留任务编号、检索来源、执行状态与异常原因 | A29 列表与 A30 详情均保留这四类字段 |
| 三、不展示完整私人对话 | A29 / A30 / A32 均写明脱敏与隐私边界，页面不展示对话正文 |
| 四、明确数据授权与隐私边界 | A32 用「数据授权与隐私边界」卡替换成长画像：列明已授权项、未收集项、可撤回与删除申请；v1.0 不保存成长档案 |

| 五、数据来源补充质量检查、索引构建与检索测试、索引版本与同步失败原因、版本回滚 | A34 增加「索引与版本」摘要卡；新增 A34b 承载质量指标、检索测试、索引版本与回滚 |

## 补充说明

- 资料状态：待审核 → 已审核（待索引发布）→ 已发布；索引构建失败进入「发布失败」，保留上一可用版本，可在数据来源页重试。
- 拒绝流程：A27「拒绝」→ 选择拒绝原因（P04）→ 资料进入「已退回」，学生端不再检索该版本。
- 「用户详情 → 处理申请」会弹出数据删除申请弹窗，提供「取消 / 拒绝处理 / 确认处理」三个动作。
- 示例数据均为虚构演示数据（王小明、U-1001、ADM-001、RUN-1024 等），不包含真实同学信息。
- 状态不以颜色单独表达，均同时给出文字（待审核 / 已发布 / 已退回 / 发布失败 / 待处理 / 在校 等）。
- 资料编辑字段与知识库实际字段对齐（来源、文号、类型、日期、适用范围、人群、时效、来源链接、附件）。
- 原型中的模型回答、文件解析、导出、认证与数据库操作尚未接入真实服务。
