# UML 用例设计

**负责人**：颜俊宇

## 内容

本目录包含 CodeMind-FZU 系统的 UML 用例设计成果（v3.1）。

建模遵循原则：**先定边界 → 再定参与者（角色）→ 用例 = 用户目标（用户目标层）→ 关系能少则少**，同时覆盖作业要求的全部交互。

- 系统边界：为学院本科生提供有官方来源、可追溯的校园事务与发展政策信息查询；
- 参与者（角色）：学生（查询者）、知识库管理员（内容维护者）；
- 用例：**1 个抽象基用例 + 9 个具体用例**（见下方「用例数量说明」）；
- 关系：5 条泛化 + 2 条 extend + 1 条 include；
- 关键用例已配规约。

## 业务范围口径（对照 PR #2、#3）

- 整体五大业务方向：政策与事务办理、升学与就业发展、竞赛与科研信息、学院资源导航、个人成长档案与长期规划；
- 首版优先支持前四个方向中有官方资料依据的查询与导航，第五个方向为后续迭代；
- **三个代表性测试任务**：竞赛认定、奖学金申请、推免基本条件，仅用于验证共用 Agent 流程，不代表业务方向数量；
- **交换与出国交流**属于「升学与就业发展」方向下的具体事项，资料不足，不作为首版确定交付。

## 用例数量说明

用例图共 **1 个抽象基用例 + 9 个具体用例**：

- 抽象基用例 `查询校园事务信息`：仅用于统一 5 个查询类用例的泛化关系，不独立计数为交付功能；
- 具体用例 9 个（UC-01 ~ UC-09）：学生侧 7 个（5 个查询目标 + 2 个扩展交互）、知识库管理员侧 2 个。

## 设计要点

- **参与者是角色，不是部门**：学生（查询者）、知识库管理员（内容维护者）。
- **用例是目标，不是功能点**：5 个查询类用例是「查询校园事务信息」的特例（泛化）；「补充信息追问」「查看回答依据」是可选扩展交互（extend）。
- **关系克制**：泛化 5 条（查询特例）、extend 2 条（可选交互）、include 1 条（核验是维护与索引发布的必然环节）。
- **知识库维护闭环**：核验 → 双索引构建 → 质量闸门 → 离线测试 → 人工审核 → 原子切换发布，失败保留上一版可用索引。
