# UML 用例设计

**负责人**：颜俊宇

## 内容

本目录包含 CodeMind-FZU 系统的 UML 用例设计成果（v3.3）。

建模遵循原则：**先定边界 → 再定参与者（角色）→ 用例 = 用户目标（用户目标层）→ 关系能少则少**，同时覆盖作业要求的全部交互。

- 系统边界：为学院本科生提供有官方来源、可追溯的校园事务与发展政策信息查询；
- 参与者（角色）：学生（查询者）、知识库管理员（内容维护者）；
- 用例：**1 个抽象基用例 + 9 个具体用例**（见下方「用例数量说明」）；
- 关系：4 条泛化 + 2 条 extend + 1 条 include；
- 关键用例已配规约。

## 业务范围口径（对齐整体功能蓝图）

整体五大业务方向，对应首版（v1.0）查询目标：

| 业务方向 | 首版（v1.0）范围 |
|---|---|
| 政策与事务办理 | 官方资料查询（奖学金、评优、申请条件与办理流程） |
| 升学与就业发展 | 推免规则查询（推免政策、升学要求、发展规划） |
| 竞赛与科研信息 | 竞赛认定查询（竞赛认定、赛事信息、科研机会） |
| 学院资源导航 | 学院官方资料查询（实验室、导师方向、本科生科研资源） |
| 个人成长档案与长期规划 | v2.0 及以后，后续迭代方向 |

- 首版优先支持前四个方向中有官方资料依据的查询与导航，第五个方向为后续迭代；
- **三个代表性测试任务**：竞赛认定、奖学金申请、推免基本条件，仅用于验证共用 Agent 流程，不代表业务方向数量。

## 用例数量说明

用例图共 **1 个抽象基用例 + 9 个具体用例**：

- 抽象基用例 `查询校园事务信息`（标注 `<<abstract>>`）：仅用于统一 4 个查询类用例的泛化关系，不独立计数为交付功能；
- 具体用例 9 个（UC-01 ~ UC-09）：学生侧 7 个（4 个查询目标 + 2 个扩展交互 + 1 个反馈）、知识库管理员侧 2 个。

## 设计要点

- **参与者是角色，不是部门**：学生（查询者）、知识库管理员（内容维护者）。
- **用例是目标，不是功能点**：4 个查询类用例是「查询校园事务信息」的特例（泛化）；「补充信息追问」「查看回答依据」是可选扩展交互（extend）。
- **关系克制**：泛化 4 条（查询特例）、extend 2 条（可选交互）、include 1 条（核验是维护流程的必备环节）。
- **知识库维护闭环**：核验 → 索引构建 → 质量检查 → 离线测试 → 人工审核 → 版本发布，失败保留上一版可用版本（技术组件细节见架构设计）。
- **状态字段对齐**：来源核验、时效核验、政策生命周期三态分离，对应数据库 `document_versions` 的 `source_verification_status`、`timeliness_verification_status`、`policy_status`。
