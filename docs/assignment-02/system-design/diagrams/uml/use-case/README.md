## 设计要点

- **参与者（角色）**：学生（查询者）、知识库管理员（内容维护者）。
- **系统边界**：为学院本科生提供有官方来源、可追溯的校园事务与发展政策信息查询。
- **用例（用户目标层）**：9 个，覆盖四大核心场景（竞赛认定、奖学金申请、保研条件、交换与出国信息查询）及培养方案查询、知识库维护，并体现补充信息追问、查看回答依据两个扩展交互。
- **关系**：5 条泛化 + 2 条 extend + 1 条 include，遵循「关系能少则少」原则。
