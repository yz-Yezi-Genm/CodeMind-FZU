## 一、UML 元素约定

两张活动图统一使用以下 UML 符号：

| 符号 | 含义 |
|---|---|
| 实心黑圆 | 初始节点，一次查询的开始 |
| 黑环套实心圆 | 活动最终节点，一次查询的结束 |
| 圆角矩形 | 动作节点，一个可执行的处理步骤 |
| 菱形 | 决策节点，按条件选择不同控制流 |
| 黑色横条 | 分叉/汇合节点，表示并行处理的开始与结束 |
| 虚线箭头 | 返回路径，如知识库向 Agent 返回检索结果 |
| 泳道 | 按职责划分动作归属：学生、Web 前端、Agent、领域知识库 |

## 二、学生政策咨询活动图

对应文件：`学生政策咨询活动图_v1.drawio / .svg / .png`

### 2.1 控制流

1. 初始节点位于学生泳道，学生输入并提交问题；
2. 前端展示处理中状态，Agent 进行意图识别与实体抽取；
3. 决策一：关键信息是否完整。不完整时 Agent 生成追问，前端展示、学生补充，控制流沿顶部回环回到决策节点，直至信息完整；
4. Agent 发出检索请求，知识库检索并以虚线返回候选资料；
5. 决策二：是否存在候选资料。无候选资料时 Agent 拒答、前端展示无法确认提示，该分支直接走向最终节点；
6. 存在候选资料时进入证据核验，核对来源、时效与适用范围；
7. 决策三：证据是否充分，分三个出口：
   - 充分：组织回答并附来源引用，前端渲染，学生阅读反馈后到达最终节点；
   - 冲突：前端说明版本差异与不确定性；
   - 不足：前端标注限制，建议线下核实。

### 2.2 设计要点

追问循环只有一个出口，即信息完整后才允许检索，从流程上杜绝带缺失条件的猜测式回答。冲突与不足分支不与最终回答汇合，而是作为独立终止路径，语义上与"给出确定答案"明确区分。

## 三、竞赛认定查询活动图

对应文件：`竞赛认定查询活动图_v1.drawio / .svg / .png`

该图对应代表性任务"某项竞赛如何认定，对综合素质评价和推免有什么影响"，并与需求文档中的验收用例 TC-01~TC-07 对应。

### 3.1 控制流

1. 学生输入竞赛名称、年份与用途，经前端提交、Agent 初步解析；
2. 决策零：条件是否齐全。不齐全时针对性追问并循环（对应 TC-02）；
3. 条件齐全后进入分叉节点，同时启动三个并行检索：竞赛认定规则、综评办法、推免办法，三个检索在知识库泳道并行执行，再由汇合节点收齐；
4. 决策一：检索/模型调用是否成功。失败时前端给出失败提示、不伪造结果（对应 TC-07）；
5. 决策二：三类资料是否各自有可靠依据，按情况进入不同提示：
   - 无依据：对应事项说明无法确认（TC-03）；
   - 版本不同：说明年份与适用范围差异（TC-04）；
   - 时效未确认：标注核验状态（TC-06）；
6. 依据齐全时，Agent 分事项独立组织结论，不把某一事项的规则推断到另一事项（TC-05）；
7. 前端展示结论与可核对来源（TC-01），学生阅读反馈后到达最终节点。

### 3.2 与验收用例的映射

| 用例 | 活动图中的位置 |
|---|---|
| TC-01 资料充分 | 汇合后依据齐全，分事项组织结论并展示来源 |
| TC-02 条件不足 | 决策零与追问循环 |
| TC-03 无可靠资料 | 决策二"无依据"分支 |
| TC-04 版本不同 | 决策二"版本不同"分支 |
| TC-05 多事项分别处理 | 分叉并行检索与分事项独立组织结论 |
| TC-06 时效未确认 | 决策二"时效未确认"分支 |
| TC-07 检索或模型异常 | 决策一失败分支 |

## 四、与业务流程图的区别

业务流程图（`../../business-process/`）面向业务读者，用常规流程图符号描述角色间的信息流转，还包含管理员侧的资料维护主线；活动图严格遵循 UML 语法，通过泳道、决策节点和同步条精确表达控制流，目前聚焦学生问答与竞赛场景。两组图内容同源、表达视角不同，在系统设计说明书中配合使用。
