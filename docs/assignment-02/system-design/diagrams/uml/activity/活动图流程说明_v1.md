## 一、UML 元素约定

两张活动图统一使用以下 UML 符号：

| 符号 | 含义 |
|---|---|
| 实心黑圆 | 初始节点，一次查询的开始 |
| 黑环套实心圆 | 活动最终节点，一次查询的结束 |
| 圆角矩形 | 动作节点，一个可执行的处理步骤 |
| 菱形 | 决策节点，按条件选择不同控制流，分支标注是/否 |
| 黑色横条 | 分叉/汇合节点，表示并行处理的开始与结束 |
| 虚线箭头 | 返回路径，如知识库向 Agent 返回检索结果 |
| 泳道 | 按职责划分动作归属：学生、Web 前端、Agent、领域知识库 |

## 二、学生政策咨询活动图

对应文件：`学生政策咨询活动图_v1.drawio / .svg / .png`

### 2.1 控制流

1. 初始节点位于学生泳道，学生输入并提交问题；
2. 前端展示处理中状态，Agent 进行意图识别与实体抽取；
3. 决策一：关键信息是否完整。不完整时 Agent 生成追问，前端展示、学生补充，控制流沿左侧回环回到决策节点，直至信息完整；
4. Agent 发出检索请求，知识库检索并以虚线返回候选资料；
5. 决策二：是否存在候选资料。无候选资料时进入可选联网核验判断；
6. 决策三：是否启用联网核验。启用时 Agent 联网查询官方公开来源（仅采信官方来源），进入决策四；不启用则前端展示无法确认提示并终止；
7. 决策四：是否获得官方依据。获得依据时与本地候选汇合进入证据核验；未获得则走向无法确认提示；
8. 证据核验同时检查**证据充分性与时效有效性**，即来源是否足以支持结论、资料是否仍在有效期内；
9. 决策五：证据充分且时效有效。通过时组织回答并附来源引用，前端渲染、学生阅读反馈后到达最终节点；不通过时前端提示证据不足或冲突及限制，作为独立终止路径。

### 2.2 设计要点

追问循环只有一个出口，即信息完整后才允许检索，从流程上杜绝带缺失条件的猜测式回答。联网核验是可选分支，联网结果不直接成答，必须回到证据核验按同一标准处理。证据不足与冲突分支不与正常回答汇合，语义上与"给出确定答案"明确区分。

## 三、竞赛认定查询活动图

对应文件：`竞赛认定查询活动图_v1.drawio / .svg / .png`

该图对应代表性任务"某项竞赛如何认定，对综合素质评价和推免有什么影响"，并与需求文档中的验收用例 TC-01~TC-07 对应。

### 3.1 控制流

1. 学生输入竞赛名称、年份与用途，经前端提交、Agent 初步解析；
2. 决策零：条件是否齐全。不齐全时针对性追问并循环（对应 TC-02）；
3. 条件齐全后进入分叉节点，**同时启动三个并行检索：竞赛认定规则、综评办法、推免办法**，三个检索在知识库泳道并行执行，再由汇合节点收齐；
4. 决策一：检索调用是否成功。检索失败时前端给出失败提示、不伪造结果（对应 TC-07 中的检索异常）；
5. 检索成功后由模型**生成回答草稿**，此时内容还不是最终回答，不能直接展示；
6. 决策二：模型调用是否成功。模型服务异常时前端给出异常提示（对应 TC-07 中的模型异常）；
7. 模型成功后，对检索到的资料**逐项进行证据核验**，核对来源、年份、适用范围和政策时效；
8. 决策三：各事项依据是否充分，分三个出口——全部充分、部分充分、全部不足；
9. 无论哪个出口，都进入分事项独立组织结论：有可靠依据的事项正常给出结论，缺少依据的事项单独说明无法确认，**不因为一类资料缺失就拒绝回答全部内容**，也不把某一事项的规则推断到另一事项（TC-05）；
10. 前端展示最终回答与可核对来源（TC-01），学生阅读反馈后到达最终节点。

### 3.2 草稿与最终回答的区别

模型生成的回答草稿只是待核验的中间产物，必须经过逐项证据核验和分事项判断后，才作为最终回答展示。这样可以把"模型写了什么"和"证据支持什么"分开，避免草稿里未经证实的内容直接到达学生侧。

### 3.3 分事项独立判断

三个检索方向对应三个独立事项，证据核验逐项进行。决策三的三个出口都不整体拒答：

| 出口 | 最终回答的组织方式 |
|---|---|
| 全部充分 | 三个事项都给出带来源的结论 |
| 部分充分 | 有依据的事项正常回答，缺依据的事项单独提示无法确认，两部分并存 |
| 全部不足 | 各事项分别说明无法确认，并给出核实建议 |

### 3.4 检索与模型两个判断分开的原因

检索调用与模型调用是两类不同的异常：前者是知识库没有返回结果或检索过程出错，后者是检索成功后模型服务不可用或返回异常。将两个决策节点分开，异常提示和处理路径才能各自对应，避免把检索失败误报成模型问题，或反过来。

### 3.5 与验收用例的映射

| 用例 | 活动图中的位置 |
|---|---|
| TC-01 资料充分 | 分事项组织结论并展示来源 |
| TC-02 条件不足 | 决策零与追问循环 |
| TC-03 无可靠资料 | 决策三对应事项的无法确认处理（不影响其他事项回答） |
| TC-04 版本不同 | 逐项核验中对年份与适用范围差异的处理 |
| TC-05 多事项分别处理 | 分叉并行检索与分事项独立组织结论 |
| TC-06 时效未确认 | 逐项核验中的政策时效检查 |
| TC-07 检索或模型异常 | 决策一（检索）与决策二（模型）两个失败分支 |

## 四、与业务流程图的区别

业务流程图（`../../business-process/`）面向业务读者，用常规流程图符号描述角色间的信息流转，还包含管理员侧的资料维护主线；活动图严格遵循 UML 语法，通过泳道、决策节点和同步条精确表达控制流，目前聚焦学生问答与竞赛场景。两组图内容同源、表达视角不同，控制流与分支保持一致，在系统设计说明书中配合使用。
