## 1. 文档目的

本文在第一次作业已确定的产品定位与技术方向基础上，给出第二次作业所需的系统技术架构、组件职责、数据流、可信性边界和后续演进方案。

CodeMind-FZU 面向福州大学计算机相关专业本科生，目标是把分散的学校与学院官方信息转化为可查询、可理解、可追溯的行动建议。项目整体业务范围与团队博客 2.4.2 的五大功能方向保持一致。

本文不把规划能力写成已实现能力。完整系统尚未完成真实 Qwen 调用、混合检索效果验证、正式资料接入和端到端联调。

### 1.1 五大业务方向与首版验证范围

| 整体业务方向 | 首版策略 |
|---|---|
| 政策与事务办理 | 奖学金、评优、申请条件和办理流程；优先支持有官方资料依据的查询 |
| 升学与就业发展 | 推免政策、升学要求和发展规划；优先支持有资料依据的政策查询 |
| 竞赛与科研信息 | 竞赛认定、赛事信息和科研机会；优先支持已有官方资料查询 |
| 学院资源导航 | 实验室、导师方向和本科生科研资源；优先支持可核实的查询与导航 |
| 个人成长档案与长期规划 | 成长经历记录、阶段目标和个性化发展建议；后续迭代，不纳入 v1.0 |

当前用于验证共用 Agent 流程的代表性测试任务是：竞赛认定类别及证明材料、奖学金申请条件与流程、推免基本条件。测试任务数量不代表业务方向数量。

“交换与出国”属于“升学与就业发展”方向下的具体事项，但当前知识库缺少项目要求、申请条件和办理流程资料，因此不作为首版确定交付功能。遇到相关问题时，系统应说明资料尚未收录并建议向国际合作与交流主管部门核实。

首版范围与团队产品规划保持一致，详见 [`../business-process/产品规划说明_v1.md`](../business-process/产品规划说明_v1.md)。

## 2. 首次作业确定的架构基线

开题答辩稿已经明确以下技术选择：

| 领域 | 首次作业方案 | 本文处理 |
|---|---|---|
| 前端 | HTML、CSS、JavaScript | 作为 v1.0 Web 用户入口 |
| 后端 | FastAPI | 承担请求校验、异常处理、接口与结果编排 |
| Agent | 任务识别、主动追问、工具调用建议、回答生成 | 作为逻辑模块，不拆成独立微服务 |
| 本地检索 | Embedding、Chroma、BM25 | 语义与关键词双路召回 |
| 排序 | RRF | 融合两路候选并去重 |
| 大模型 | Qwen API | 基于证据组织回答，工具建议由后端受控执行 |
| 联网工具 | Tavily | 候选能力，按需核验官方公开信息 |
| 输出约束 | 来源、年份、适用范围与证据核验 | 无依据或冲突时明确提示 |

第二次作业不得把方案改写成 PostgreSQL、pgvector、MinIO、Celery 等与首次作业不一致的既定实现。上述组件可以作为未来规模化方案重新论证，但不属于本次确定的 v1.0 技术栈。

## 3. 架构目标

1. **官方依据优先**：优先使用本地已登记、已提取正文的福大官方资料。
2. **混合检索**：语义检索解决表述差异，BM25 保留政策名称、文号、年度等精确匹配能力。
3. **证据约束生成**：Qwen 只基于检索到的证据片段组织答案，不自由补全政策结论。
4. **信息不足先追问**：缺少年级、专业、竞赛名称、年份或认定用途时，先请求补充。
5. **可追溯输出**：返回来源文件、发布日期、适用范围、核验状态和不确定性提示。
6. **渐进实现**：先完成可靠问答，再扩展动态机会推荐、历史记录和个性化发展服务。

## 4. 总体逻辑架构

系统由六个逻辑层组成：

| 层级 | 组件 | 主要职责 |
|---|---|---|
| 用户与来源 | 学生用户、知识库维护者、学校/学院官网、Tavily | 发起问题、维护资料、提供官方信息和可选联网核验 |
| Web 与 API | HTML/CSS/JS 前端、FastAPI、Ask API | 收集问题、校验请求、调用 Agent、返回答案与引用 |
| Agent 编排 | 任务识别、策略路由、主动追问、Agent 编排器、回答组织 | 判断任务类型、选择流程、处理信息缺口、组织输出 |
| 检索与证据 | 混合检索、Chroma、BM25、RRF、证据核验 | 召回候选、融合排序、校验来源、日期、适用范围与时效 |
| 外部与知识 | 本地资料、Embedding、Qwen API、Tavily、离线 PoC | 提供知识、向量化、生成与可选在线核验能力 |
| 质量保障 | 离线测试、失败降级、调用日志、资料更新记录 | 验证事实正确性、来源可追溯性与异常处理 |

图示见 [`系统技术架构图_赵紫龙_v1.svg`](系统技术架构图_赵紫龙_v1.svg)。

### 4.1 v1.0 组件边界

v1.0 可以使用单体 FastAPI 应用承载 API 与 Agent 编排逻辑，Chroma 和 BM25 作为本地索引组件运行。组件是逻辑划分，不代表已经拆分为独立部署服务。

以下能力不属于 v1.0 必须交付内容：

- 完整就业推荐；
- 科研机会动态推荐；
- 个性化升学结论；
- 交换与出国项目完整查询；
- 个人成长档案；
- 独立数据库部署、消息队列和对象存储；
- 完整后台管理 Web 应用。

后台维护在首版可以由脚本和人工审核完成，待查询闭环稳定后再建设 Web 管理端。

## 5. 首版问答链路

```text
学生输入问题
  → Web 前端
  → FastAPI /api/ask
  → 任务识别与实体抽取
  → 信息不足时由 Agent 生成主动追问
  → Embedding 与 BM25 双路检索
  → RRF 融合和去重
  → EvidenceVerifier 进行生成前证据核验
  → 向 Agent 返回 verifiedEvidence、citationIds、policyStatus
  → Agent 将问题和核验后证据提交给 Qwen API
  → Qwen API 返回回答草稿与引用候选
  → AnswerVerifier 进行生成后回答复核
  → 返回解释、来源、不确定性和下一步建议
```

### 5.1 代表性测试任务与三类处理策略

三个代表性测试任务与三类处理策略的关系如下：

| 代表性测试任务 | 使用策略 | 典型输入 | 首版处理 |
|---|---|---|---|
| 竞赛认定类别及证明材料 | 事务咨询 + 机会筛选 | “这项竞赛在学院如何认定？” | 返回有依据的认定类别、证明材料和适用规则 |
| 奖学金申请条件与流程 | 事务咨询 | “申请院级奖学金需要什么材料？” | 检索官方通知并整理条件、材料和办理流程 |
| 推免基本条件 | 事务咨询 | “推免需要满足哪些基本要求？” | 检索官方规则，明确适用范围；不预测个人结果 |

五大业务方向是产品范围，三个测试任务只用于验证共用 Agent 闭环。v1.0 可以提供有官方资料依据的政策查询、机会信息查询和阶段性准备建议；个人成长档案和个性化长期规划不在首版实现。TaskRouter 中的“规划”分支仅作为后续能力预留，不进入 v1.0 交付路径。

### 5.2 生成前证据筛选与生成后回答复核

两类核验不得混为一个步骤：

| 阶段 | 组件 | 输入 | 输出 |
|---|---|---|---|
| 生成前证据筛选 | `EvidenceVerifier` | RRF 融合候选、可选 Tavily 官方结果 | `verifiedEvidence`、`citationIds`、`policyStatus` |
| 生成 | `AgentOrchestrator` → `LLMAdapter` | 问题与已核验证据 | Qwen 回答草稿 |
| 生成后回答复核 | `AnswerVerifier` | 草稿、引用 ID、政策状态、原始证据 | 通过或拒绝的最终答案 |

### 5.3 主动追问与重新提交

缺少年级、专业、竞赛名称、年份或认定用途时，Agent 不进入最终生成阶段，而是执行以下回路：

1. TaskRouter 将缺失字段交给主动追问模块。
2. 主动追问模块生成一个最关键的问题，避免一次索要过多信息。
3. FastAPI 将 `needs_clarification`、缺失字段和问题文本返回 Web 前端。
4. 前端展示追问并保留原问题与已填写上下文。
5. 用户补充信息后，前端以同一会话或请求关联 ID 重新提交 `/api/ask`。
6. 重新提交的问题再次进入任务识别、检索和证据核验流程。

### 5.4 可信回答状态

建议接口返回 `answerStatus`：

- `grounded`：找到足够且适用的官方证据。
- `needs_clarification`：缺少年级、专业、事项、年份或用途。
- `insufficient_evidence`：本地资料和可选在线核验均无法支持确定回答。
- `conflict`：不同规则或版本冲突，需要展示来源并提示人工核验。
- `degraded`：模型或联网工具不可用，只能返回检索摘要或稍后重试提示。

## 6. 本地知识资产与检索

### 6.1 资料组织

本地知识资产由四部分组成：

| 资产 | 内容 | 作用 |
|---|---|---|
| 原始资料 | 官方 HTML、PDF、DOCX、XLSX 及附件 | 保存证据原件 |
| 中文整理稿 | 提取后的正文、标题、来源和适用范围 | 供检索与阅读 |
| CSV 元数据索引 | 记录编号、来源、日期、状态、适用对象和文件路径 | 统一登记资料 |
| 检索索引 | Chroma 向量索引与 BM25 倒排索引 | 提供混合召回 |

项目知识库的资料总量基准为 **44 条**，按政策或通知事项计数，网页与附件合并计算，共分 7 类。具体状态如下：

- 13 条已有部分核查记录，但仍有待核项；
- 31 条已完成本地文件与来源登记核查，但时效仍待联网复核；
- 44 条中 43 条已提取正文，1 条扫描版文件待 OCR。

当前仓库 `knowledge_base/政策资料/知识库索引.csv` 只有 **31 条现有索引记录**。这只是仓库中当前索引文件的记录数量，不代表知识库总量只有 31 条，也不能直接认定它与上述“31 条已做本地文件与来源登记核查”完全对应。

合并成果前必须由项目统筹和知识库维护者完成以下核对：

1. 以 44 条作为项目知识库总量基准；
2. 将新增资料与附件同步进仓库；
3. 核对 CSV 条数与正文提取数量；
4. 逐条确认当前 CSV 中 31 条记录与开题稿核查状态之间的对应关系；
5. 不把“源文件存在”表述为“政策已联网复核”。

### 6.2 混合检索

1. 查询理解阶段提取政策事项、年级、专业、年度、竞赛名称和用途。
2. Chroma 使用 Embedding 召回语义相关分块。
3. BM25 召回规则名称、文号、年度、申请条件等关键词匹配。
4. RRF 根据两路名次融合并去重。
5. 证据核验优先保留学校/学院官方来源和与当前适用对象一致的版本。

本地资料优先。只有问题需要当前动态信息且本地资料不足时，EvidenceVerifier 才向 Tavily 提交查询请求；Tavily 将搜索结果返回 EvidenceVerifier，而不是直接返回给生成模块。联网结果仍须确认官方来源，不得用搜索结果摘要直接替代原文。

### 6.3 索引可重建

资料正文、元数据或分块规则变化后，Chroma 与 BM25 索引应能从本地知识资产重新构建。索引不承担唯一事实来源的作用，原始资料、整理稿和 CSV 元数据才是可审计资产。

### 6.4 双索引版本发布

Chroma 与 BM25 必须作为同一个知识版本共同发布：

1. 两个索引在构建时使用同一个 `versionId`；
2. 两个索引均通过质量检查后，才允许进入离线测试；
3. 离线测试通过后，`IndexPublisher` 将完整版本提交给 `VersionRegistry`；
4. `VersionRegistry` 先确认 Chroma 与 BM25 均绑定该 `versionId`，再一次性切换活动版本指针；
5. `AgentQueryGateway` 只能读取完整发布的活动版本；
6. 任一索引构建、质量检查或测试失败时，不切换活动版本，Agent 继续使用上一版完整索引。

“分别激活两个索引”不等于发布完成。只有统一版本记录和活动指针切换成功后，知识资料才可供 Agent 检索。

## 7. 关键接口建议

### 7.1 问答接口

```http
POST /api/ask
Content-Type: application/json
```

```json
{
  "question": "大二申请转专业需要什么条件？",
  "context": {
    "grade": "大二",
    "major": "计算机科学与技术"
  }
}
```

成功响应示例：

```json
{
  "requestId": "req_demo",
  "answer": "根据现行办法……",
  "answerStatus": "grounded",
  "citations": [
    {
      "documentId": "fzu-transfer-2025",
      "title": "福州大学本科生转专业管理实施办法",
      "publisher": "福州大学",
      "publishedAt": "2025-05-21",
      "verifiedAt": "2026-10-21",
      "applicableGrade": ["大一", "大二"],
      "applicableMajor": "不限",
      "policyStatus": "current_reference",
      "sourceUrl": "https://example.fzu.edu.cn/official-policy",
      "sourcePath": "knowledge_base/政策资料/整理资料/学校/...",
      "locator": "第三章"
    }
  ],
  "limitations": []
}
```

首版没有登录体系时，不应伪造用户身份或持久化个人信息。`context` 仅保存当前请求需要的年级、专业和目标。

### 7.2 健康检查

```http
GET /api/health
```

至少检查 FastAPI 服务、Chroma 索引可读性和 BM25 索引加载状态。Qwen 或 Tavily 不可用不应导致健康检查整体失败，但响应必须标明外部能力状态。

### 7.3 术语、引用与政策状态字段

| 缩写/字段 | 含义 |
|---|---|
| MVP | Minimum Viable Product，首版最小可用产品 |
| API | Application Programming Interface，应用编程接口 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| BM25 | 基于词频、逆文档频率和文档长度的关键词排序算法 |
| RRF | Reciprocal Rank Fusion，倒数排名融合算法 |
| OCR | Optical Character Recognition，对扫描图片进行文字识别 |
| CSV | 逗号分隔值文件，本项目当前人工可读索引格式 |
| `requestId` | 单次请求追踪标识，用于日志、错误定位和重试关联 |
| `verifiedEvidence` | 生成前核验通过、允许提交给 Qwen 的证据片段 |
| `answerStatus` | 回答状态，取值为 `grounded`、`needs_clarification`、`insufficient_evidence`、`conflict` 或 `degraded` |
| `citations` | 支撑回答的官方证据列表，不是装饰性参考链接 |
| `citationIds` | 生成前后用于约束和复核引用的证据 ID 集合 |
| `documentId` | 知识库资料记录编号 |
| `title` | 官方资料标题 |
| `publisher` | 发布单位 |
| `sourceUrl` | 官方资料原始网址；本地资料可同时提供 `sourcePath` |
| `publishedAt` | 官方发布日期，使用 `YYYY-MM-DD` |
| `verifiedAt` | 最后一次完成来源、日期、适用范围或时效核验的日期 |
| `applicableGrade` | 资料适用的年级范围 |
| `applicableMajor` | 资料适用的专业范围 |
| `policyStatus` | 政策状态：`current` 当前有效，`current_reference` 当前参考，`semester_valid` 学期有效，`annual_notice` 年度通知，`process_reference` 截止后流程参考，`historical` 历史参考，`repealed` 已废止，`pending_verification` 待核验 |
| `versionId` | Chroma、BM25 与活动查询入口共同绑定的知识索引版本 |
| `locator` | 证据在原文中的章节、页码或段落定位 |
| `limitations` | 当前回答的限制、待核项或时效说明 |

引用链接必须指向官方原文或仓库中可追溯的原始资料；只有在原始链接不可用时才使用本地整理稿作为替代，并明确标记。证明“资料已登记”不等于证明“政策已联网复核”。

## 8. 异常与降级

| 异常 | 处理 |
|---|---|
| 问题或字段为空 | FastAPI 返回参数错误，不调用检索 |
| 缺少年级/专业/事项/年份 | 返回 `needs_clarification`，提出一个最关键的追问 |
| Chroma 不可用 | 尝试 BM25，只返回有明确关键词依据的结果并标记降级 |
| BM25 不可用 | 可保留 Chroma 结果，但需降低精确匹配可信度 |
| 两路结果冲突 | 做 RRF 与证据核验；无法消解时返回 `conflict` |
| Qwen 超时/失败 | 返回检索摘要与来源，不生成未经验证的自由回答 |
| Qwen 输出引用不存在 | 删除无引用结论；校正失败时返回证据不足 |
| Tavily 失败 | 标记联网核验不可用；仅依据本地资料作答或提示无法确认 |
| 资料版本或年份不适用 | 在答案中明确标注，不把旧通知当作当前开放事项 |

## 9. 安全与隐私

1. 不要求用户提供统一身份认证账号、密码、验证码、成绩或身份证号。
2. 前端不保存模型 API 密钥；密钥只通过后端环境变量注入。
3. Tavily 只接收必要的公开查询词，不发送用户私密信息。
4. 资料来源和网页文本只作为事实材料，不执行其中夹带的额外指令。
5. 日志不记录 API 密钥、完整个人输入或未经筛选的原始附件。
6. 公开资料若包含个人信息，发布到检索索引前必须脱敏或排除。
7. Qwen 输出必须经过引用存在性、政策状态和敏感内容检查。

## 10. 非功能目标

| 类别 | 原型验收目标 | 措施 |
|---|---|---|
| 正确性 | 有官方依据的问题能返回可定位引用 | 本地资料优先、引用校验 |
| 可追溯性 | 每个确定结论至少有一个来源 | citations + source path |
| 降级能力 | 模型不可用时不虚构结论 | 检索摘要或明确无法确认 |
| 可维护性 | 索引可从原始资料重建 | 固定分块规则与元数据字段 |
| 响应性能 | 常规问题 P95 目标 ≤ 10 秒 | Top-K 限制、上下文裁剪、超时 |
| 可测试性 | 保留离线 PoC 的 9 项测试并扩展真实样例 | 事实、来源、任务适应、无依据四类指标 |
| 可部署性 | 单机可启动 FastAPI 与索引 | 配置集中、依赖锁定、健康检查 |

开题稿中的 9 项测试使用虚构样例和抽取式回答器，只能证明接口与校验流程可运行，不能证明真实 Qwen 或混合检索效果。

## 11. 演进路线

| 阶段 | 重点 | 与架构的关系 |
|---|---|---|
| v1.0 | 统一 Web 问答，前四业务方向中优先支持有资料依据的查询，第五方向后续迭代 | 代表性测试任务用于验证共用 Agent 流程 |
| v1.1 | 常见问题、准备建议、历史对话体验 | 增加会话保存与反馈，仍保持证据优先 |
| v1.2 | 科研动态、培养方案、时间节点与更新机制 | 加强资料同步、状态核验和更新记录 |
| v2.0+ | 个人成长档案、阶段目标、个性化推荐 | 在隐私与数据治理条件成熟后评估 |

ESP32 智能桌面终端属于可选探索，不纳入 v1.0。若后续实施，硬件只是 Web/API 的另一种输入输出入口，不能绕过后端 Agent、证据核验与真实任务状态。

## 12. 主要取舍

| 决策 | 优点 | 限制 |
|---|---|---|
| 本地资料优先 | 来源可控、可离线复现 | 资料更新需要维护流程 |
| Chroma + BM25 + RRF | 兼顾语义与精确匹配 | 需要调参与效果测试 |
| Qwen API 负责生成 | 快速获得自然语言能力 | 依赖网络、成本和模型稳定性 |
| 后端受控工具建议 | 防止模型任意调用外部能力 | 工具路由逻辑需要额外测试 |
| Tavily 作为候选 | 可补充动态官方信息 | 搜索结果仍需回到官方原文核验 |
| v1.0 是否部署数据库待确认 | 可降低首版复杂度 | 若数据库设计负责人确认纳入，需要补充部署与迁移约束 |
