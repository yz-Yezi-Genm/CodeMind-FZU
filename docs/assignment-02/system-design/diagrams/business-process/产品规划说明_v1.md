# CodeMind-FZU 产品规划说明

**版本**：v1.0
**日期**：2026-11-08

---

## 一、产品定位

CodeMind-FZU 是面向福州大学计算机与大数据学院（软件学院）本科生的校园事务与发展信息智能助手。它不替代学校、学院的官方发布渠道，而是把分散在不同官网、通知和附件中的资料集中整理，通过领域知识库和 Agent 任务流程，让学生用一次自然语言提问就能查到有来源、可核对的答案。

通用大模型可以回答常识性问题，但回答具体年份的奖学金条件、竞赛认定类别或推免政策时容易脱离依据。本产品的核心价值在于：**回答必须能追溯到官方资料，证据不足时明确说明，而不是给出一个看似确定的答案。**

## 二、目标用户

主要用户为学院本科生，重点服务大一至大三学生：

- **大一学生**：关注学籍、选课、考试、转专业等基础事务；
- **大二学生**：开始接触竞赛、创新学分、奖学金和辅修；
- **大三学生**：重点关注推免、升学、科研实践和实验室机会。

问卷样本中大二、大三学生合计占 90.48%，因此首版场景优先围绕这两个年级的高频问题设计，同时保留对大一事务的覆盖。

## 三、需求依据

2026 年 10 月面向计算机相关专业学生发放问卷，回收有效样本 84 份。以下结论只代表本次小样本探索性调查，不外推为全体学生意见。

| 调研发现 | 数据 | 对产品的直接影响 |
|---|---|---|
| 信息分散，不知道从哪里找 | 64/84（76.19%） | 建立统一查询入口，优先整合官方来源资料 |
| 担心信息不准确 | 64/84（76.19%） | 回答展示来源、版本和适用范围，证据不足时拒答 |
| 缺少针对年级和专业的建议 | 52/84（61.90%） | 必要时追问年级、专业、用途，再组织回答 |
| 缺少过来人经验参考 | 52/84（61.90%） | 经验类材料首版暂不纳入，先评估审核机制 |
| 升学与就业发展重要程度最高 | 4.43/5；保研/升学规划单选占 42.9% | 推免与升学政策查询作为优先验证方向 |
| 学院资源导航重要程度 4.38/5 | 单选优先项占 19.1% | 培养方案与办事渠道查询作为重要方向 |

## 四、功能总体规划

产品采用 Web 软件形式，整体规划五大业务方向。自然语言问答、任务识别、知识检索、来源展示、证据核验和必要追问属于支撑这五大方向的**共用技术能力**，不单独算作业务模块。

| 功能方向 | 说明 | v1.0 范围 |
|---|---|---|
| 政策与事务办理 | 奖学金、评优评奖等事务的条件、材料与流程 | 优先支持有官方依据的查询 |
| 升学与就业发展 | 推免、升学政策及阶段性准备事项 | 优先官方政策查询，个性化规划后续迭代 |
| 竞赛与科研信息 | 竞赛认定规则、科研实践资料与机会 | 优先已有官方资料查询，动态机会筛选后续完善 |
| 学院资源导航 | 培养方案、办事渠道、学习科研资源 | 优先资料查询与导航 |
| 个人成长档案与长期规划 | 基于用户主动提供的信息整理目标与经历 | 后续迭代，不纳入 v1.0 交付 |

## 五、v1.0 范围（MVP）

v1.0 只交付一条完整、可靠的核心查询闭环：

```
学生提出问题 → 信息不足时追问 → 检索领域知识库 → 证据核验
        → 证据充分：组织回答并展示来源
        → 证据不足/版本冲突/时效未确认：如实提示，不编造结论
```

**v1.0 明确不做**：完整的个性化升学规划、个人成长档案、动态机会自动推送、经验帖类 UGC 内容，以及 ESP32 硬件联动。这些方向在核心闭环稳定、数据使用规则明确后再评估。

v1.0 可以提供有官方资料依据的政策查询、机会信息查询和阶段性准备建议，但不保存个人成长档案，也不生成个性化长期规划或成长建议。

代表性场景为"某项竞赛在学院如何认定，对综合素质评价和推免有什么影响"，用于验证检索、证据核验和多事项分别处理的能力，但系统并不局限于竞赛查询。

## 六、迭代路线

| 阶段 | 主要工作 | 检查点 |
|---|---|---|
| 一：完善领域资料 | 完成待 OCR 文件，逐条核验来源、日期、适用范围与时效 | 资料清单与核验状态完整，未核实资料有标记 |
| 二：接入检索与 Agent | 确定检索方案，用真实资料测试，集成模型 API 与追问 | 代表性问题能完成"理解—检索—回答"并展示来源 |
| 三：前后端集成 | 前端与 FastAPI 后端联调，覆盖输入校验与异常分支 | 前端可发起查询并收到结构清楚的回答或失败提示 |
| 四：测试与改进 | 按固定用例检查事实正确性、来源、适用范围与拒答 | 测试记录与问题清单完整，未通过用例如实标记 |
| 五：部署与验收 | 完成部署、使用说明与验收材料 | 实际可访问的地址及对应测试记录 |

## 七、关键设计原则

1. **官方来源优先**：资料只收录学校、学院官方渠道，记录发布部门、日期、链接和核验状态；
2. **版本可追溯**：同一事项的不同版本分别保存，过期资料标记为历史参考，不直接删除；
3. **不确定性显性化**：资料不足、冲突或时效无法确认时，提示限制并建议线下核实；
4. **信息最小化**：只收集完成当前任务所必需的信息，年级、专业、目标等由用户在必要时主动提供；
5. **不提前宣称效果**：领域定制是否优于通用模型，以真实资料接入后的对照实验数据为准。
