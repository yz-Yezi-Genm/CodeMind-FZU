# CodeMind-FZU 业务流程说明

**版本**：v1.6
**日期**：2026-11-08

---

## 一、角色与对象

业务流程涉及四类角色和对象：

| 角色/对象 | 职责 |
|---|---|
| 学生 | 提出问题，在信息不足时补充条件，阅读回答并反馈 |
| Web 前端 | 接收输入、展示处理状态、追问和最终回答及来源 |
| Agent | 识别意图、判断信息是否完整、发起检索、核验证据并组织回答 |
| 领域知识库 | 保存官方资料及其来源、日期、适用范围和核验状态，由管理员维护 |

系统业务由两条主线构成：**学生侧的问答流程**回答问题，**管理员侧的资料维护流程**保障知识库内容可靠，两者通过"发布入库与索引更新"衔接。

## 二、业务范围与五大功能方向

本产品的整体业务范围以团队博客 2.4.2《核心功能规划》为准，共五大功能方向。两张业务流程图描述的是其中的代表性任务和共用处理环节，不代表业务范围只包含图中画出的内容。

| 功能方向 | 业务范围 | 首版安排 |
|---|---|---|
| 政策与事务办理 | 奖学金、评优评奖及其他校园事务的条件、材料与流程 | 优先支持有官方资料依据的查询 |
| 升学与就业发展 | 推免、升学及相关发展政策与阶段性准备事项 | 优先支持官方政策查询，个性化规划逐步迭代 |
| 竞赛与科研信息 | 竞赛认定规则、科研实践资料与机会信息 | 优先支持已有官方资料的查询，动态机会筛选后续完善 |
| 学院资源导航 | 培养方案、学院资源、办事渠道、本科生学习科研资源 | 优先支持资料查询与导航 |
| 个人成长档案与长期规划 | 基于用户主动提供的信息整理目标与经历 | 后续迭代，不作为 v1.0 必要交付 |

前四个方向优先支持有官方资料依据的查询与导航，第五个方向属于后续迭代。后面第三节的学生问答流程是前四个方向共用的查询闭环，第四节的维护流程支撑全部方向的资料更新。

## 三、学生问答主业务流程

对应文件：`学生问答业务流程_v1.drawio / .svg / .png`

### 3.1 主流程

1. 学生输入自然语言问题；
2. Agent 识别意图与任务类型；
3. 判断关键信息（事项名称、年份、年级专业、用途等）是否完整；
4. 信息完整后检索领域知识库；
5. 判断是否检索到可靠候选资料；
6. 对候选资料进行证据核验，核对来源、发布日期、适用范围和核验状态；
7. 判断证据是否充分且时效有效；
8. 证据充分时组织回答，说明结论、适用条件和来源引用；
9. 前端展示回答与来源链接，并收集用户反馈。

### 3.2 分支与退回

| 分支 | 处理方式 | 对应需求 |
|---|---|---|
| 关键信息不完整 | 追问缺失信息，学生补充后重新判断，不自行猜测 | FR-03 |
| 知识库无候选资料 | 可选择联网核验官方公开信息；不启用或仍无可靠依据则拒答 | FR-04、FR-07 |
| 联网获得可靠依据 | 回到证据核验环节，与本地候选资料按同一标准处理 | FR-04 |
| 证据不足或时效未确认 | 提示限制与核验状态，建议线下核实 | FR-06、FR-07 |
| 资料版本冲突 | 并列说明各版本年份与适用范围差异，提示进一步核实 | FR-08 |

所有判断节点的分支均标注"是/否"。异常和拒答分支统一汇入汇合点后结束，保证一次查询只有两种结局：**带来源的回答，或明确的无法确认提示**，不会出现无依据的确定性结论。

### 3.3 可选联网核验

联网核验是可选流程，不是每次查询的必经环节，仅在本地知识库无候选资料时才考虑是否启用，且必须满足两个约束：

- **只查询官方公开来源**（学校、学院及相关主管部门的官方网站），不直接采信普通搜索引擎返回的任意结果；
- 联网获得的内容不能直接当作答案，必须回到**证据核验环节**，核对来源真实性、发布日期、适用范围和时效后，才允许进入回答组织。

未启用联网、联网未获得官方依据，或依据未通过核验的，统一按拒答处理。

## 四、知识库资料维护业务流程

对应文件：`知识库维护业务流程_v1.drawio / .svg / .png`

### 4.1 主流程

1. 定期扫描学校、学院官方渠道；
2. 判断是否发现新资料或新版本；未发现则结束本轮扫描，等待下一次扫描；
3. 登记元数据：名称、发布单位、文号、日期、原文链接；
4. 采集原始文件（网页或附件）并提取正文；
5. 人工核验来源真实性、日期、适用范围和政策时效；
6. 标注政策状态：当前有效、学期有效、待核验、历史参考、已废止；
7. 资料质量检查：引用存在性、政策状态、敏感内容脱敏；
8. 双索引构建：ChromaBuilder 构建向量索引、BM25Builder 构建倒排索引，两者使用同一个 versionId；
9. QualityGate 质量闸门汇总双索引与元数据状态，双索引均 PASS 才进入 PoCTestSuite；
10. PoCTestSuite 运行离线 PoC 测试，测试结果回到 QualityGate；
11. 人工审核与发布许可；
12. IndexPublisher 提交发布事务，VersionRegistry 同版本绑定并原子切换，AgentQueryGateway 提供活动索引；
13. 定期复核，对到期或失效资料变更状态。

### 4.2 退回循环

- 正文提取失败（如扫描件）：标记待 OCR/待处理，退回重新采集处理，对应当前知识库中 1 条待 OCR 资料的情况；
- 核验不通过：标记待核验并退回修正，不允许带着问题直接发布。

### 4.3 版本处理

当资料属于已有事项的新版本时，旧版本转为历史参考或已废止状态，**保留记录不删除**，新版本单独登记。这样 Agent 在回答时可以区分现行政策与历史通知，避免把过期条件当作当前要求。

### 4.4 质量闸门与双索引版本发布

资料不是保存到知识库后立即可用，发布流程与 PR #2 通信设计保持一致。Chroma 与 BM25 必须作为同一个知识版本共同发布：

1. ChromaBuilder、BM25Builder 构建时使用同一个 versionId，并分别向 QualityGate 返回索引状态；
2. QualityGate 汇总双索引与元数据状态，只有双索引均为 PASS 才允许进入 PoCTestSuite；
3. PoCTestSuite 运行检索、引用、冲突和无依据处理的离线 PoC 测试，测试失败不得进入发布；
4. 测试通过并取得人工审核与发布许可后，IndexPublisher 将完整版本提交给 VersionRegistry；
5. VersionRegistry 确认两个索引均绑定该 versionId 后，一次性原子切换活动版本指针；
6. AgentQueryGateway 只读取完整发布的活动版本，为 Agent 提供可检索索引，并隔离构建中或未完成的索引。

**失败不替换当前版本**：任一索引构建、QualityGate 检查、离线 PoC 测试或发布环节失败，本轮发布中止，不切换活动版本指针，Agent 继续使用上一版完整可用索引，构建中的索引不会被 Agent 使用，也不会出现只激活单个索引的半成品状态。

索引可从原始资料和元数据重新构建，不承担唯一事实来源的作用；原始资料、整理稿与 CSV 元数据才是可审计的事实来源。

## 五、知识库现状与数据口径

### 5.1 资料总量

截至当前，知识库**已登记资料总量为 44 条**，统计口径为：按政策或通知事项计一条，网页与其附件合并计算；仅发现但尚未收录的链接不计入。44 条资料分为七类：学籍与学生事务 4、课程考试与教务 13、综评与奖学金 6、竞赛认定与创新学分 7、培养方案与学位 8、科研实践与实验室 2、推免与升学 4。

### 5.2 两组不同的状态数据

44 条资料对应两组互相独立的状态数据，不能混为一谈：

| 状态维度 | 数量分布 | 含义 |
|---|---|---|
| 核查状态 | 13 条 / 31 条 | 13 条已有部分官方来源、日期、范围或内容核查记录但仍有待核项；其余 31 条完成本地文件与来源登记，政策时效待逐条联网复核。13+31=44 |
| 正文提取状态 | 43 条 / 1 条 | 43 条已提取正文；1 条扫描版高水平科创奖励办法待 OCR。43+1=44 |

### 5.3 关于 CSV 的 31 条记录

当前仓库 `knowledge_base/政策资料/知识库索引.csv` 只有 **31 条记录**，与 44 条登记总量不一致，说明索引快照与人工登记尚未同步。需要注意：

- 这个"CSV 31 条"是索引文件的记录数，与 5.2 中"待联网复核的 31 条"只是数字相同，**含义完全不同，不能互相替代**；
- CSV 记录不代表知识库总量，其完整性由知识库负责人核对，补齐后才能作为完整索引使用；
- 任何文档都不应把 31 条写成知识库总量，总量以人工登记的 44 条为准。

### 5.4 边界说明与功能状态

知识库尚未正式接入 Agent，两张流程图描述的是设计目标流程，其中"发布入库可被检索""证据核验""索引构建"等环节需在后续开发和测试中实际验证，不能视为已全部实现。为避免把规划当成已完成能力，流程涉及的功能按三类区分：

| 功能状态 | 含义 | 本流程中的对应内容 |
|---|---|---|
| 计划功能 | 已规划、尚未实现 | 正式接入 Agent 的检索调用、Web 管理端、动态机会筛选 |
| 已实现功能 | 当前可运行或已完成 | 资料登记、元数据与正文整理、离线 PoC 的部分逻辑 |
| 待验证功能 | 已搭建但需真实资料和测试确认 | 双索引发布、证据核验、联网核验、异常分支处理 |
