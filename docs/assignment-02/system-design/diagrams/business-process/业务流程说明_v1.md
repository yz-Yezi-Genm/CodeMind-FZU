# CodeMind-FZU 业务流程说明

**版本**：v1.0
**日期**：2026-11-08

---

## 一、角色与对象

业务流程涉及四类角色和对象：

| 角色/对象 | 职责 |
|---|---|
| 学生 | 提出问题，在信息不足时补充条件，阅读回答并反馈 |
| Web 前端 | 接收输入、展示处理状态、追问和最终回答及来源 |
| Agent | 识别意图、判断信息是否完整、发起检索、核验证据并组织回答 |
| 领域知识库 | 保存官方资料及其来源、日期、适用范围和核验状态，由管理员维护 |

系统业务由两条主线构成：**学生侧的问答流程**回答问题，**管理员侧的资料维护流程**保障知识库内容可靠，两者通过"发布入库"衔接。

## 二、学生问答主业务流程

对应文件：`学生问答业务流程_v1.drawio / .svg / .png`

### 2.1 主流程

1. 学生输入自然语言问题；
2. Agent 识别意图与任务类型；
3. 判断关键信息（事项名称、年份、年级专业、用途等）是否完整；
4. 信息完整后检索领域知识库；
5. 对候选资料进行证据核验，核对来源、发布日期、适用范围和核验状态；
6. 证据充分时组织回答，说明结论、适用条件和来源引用；
7. 前端展示回答与来源链接，并收集用户反馈。

### 2.2 分支与退回

| 分支 | 处理方式 | 对应需求 |
|---|---|---|
| 关键信息不完整 | 追问缺失信息，学生补充后重新判断，不自行猜测 | FR-03 |
| 知识库无候选资料 | 可选择联网核验官方公开信息；仍无可靠依据则拒答 | FR-04、FR-07 |
| 联网获得可靠依据 | 回到证据核验环节，按正常路径处理 | FR-04 |
| 证据不足或时效未确认 | 提示限制与核验状态，建议线下核实 | FR-06、FR-07 |
| 资料版本冲突 | 并列说明各版本年份与适用范围差异，提示进一步核实 | FR-08 |

所有异常和拒答分支统一汇入汇合点后结束，保证一次查询只有两种结局：**带来源的回答，或明确的无法确认提示**，不会出现无依据的确定性结论。

## 三、知识库资料维护业务流程

对应文件：`知识库维护业务流程_v1.drawio / .svg / .png`

### 3.1 主流程

1. 定期扫描学校、学院官方渠道，发现新资料或新版本；
2. 登记元数据：名称、发布单位、文号、日期、原文链接；
3. 采集原始文件（网页或附件）并提取正文；
4. 人工核验来源真实性、日期、适用范围和政策时效；
5. 标注政策状态：当前有效、学期有效、待核验、历史参考、已废止；
6. 发布入库，资料方可被 Agent 检索调用；
7. 定期复核，对到期或失效资料变更状态。

### 3.2 退回循环

- 正文提取失败（如扫描件）：标记待 OCR/待处理，退回重新采集处理，对应当前知识库中 1 条待 OCR 资料的情况；
- 核验不通过：标记待核验并退回修正，不允许带着问题直接发布。

### 3.3 版本处理

当资料属于已有事项的新版本时，旧版本转为历史参考或已废止状态，**保留记录不删除**，新版本单独登记。这样 Agent 在回答时可以区分现行政策与历史通知，避免把过期条件当作当前要求。

## 四、现状与边界

截至当前，知识库已登记 44 条资料，其中 43 条完成正文提取、13 条有部分核查记录；知识库尚未正式接入 Agent。因此两张流程图描述的是设计目标流程，其中"发布入库可被检索""证据核验"等环节需在后续开发和测试中实际验证，不能视为已全部实现。

## 五、与其他设计图的关系

- UML 活动图（`../uml/activity/`）用规范 UML 符号表达同一批流程的控制流与分支；
- 功能结构图（`../function/`）描述系统模块分解，不涉及流程顺序；
- Agent 内部组件调用与时序由 `../agent-flow/`、`../uml/sequence/` 负责，本流程只描述到 Agent 的业务动作层级。
