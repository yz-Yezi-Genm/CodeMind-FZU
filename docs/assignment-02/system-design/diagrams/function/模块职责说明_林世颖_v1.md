## 一、系统概述

CodeMind-FZU 是面向福州大学计算机与大数据学院（软件学院）本科生的智能学习助手，核心目标是为学生提供选课、考试、奖学金、综评、转专业、竞赛、实验室、推免等政策的智能问答与信息查询服务。

系统整体采用前后端分离架构，划分为**学生端服务**、**后台管理端**和**Agent 核心服务**三大功能模块，形成"前端交互—后端管理—智能引擎"的三层功能体系。

---

## 二、功能结构图说明

系统功能结构图采用三层分解：

- **第一层（顶层）**：CodeMind-FZU 智能学习助手系统
- **第二层（一级模块）**：学生端服务、后台管理端、Agent 核心服务
- **第三层（二级子模块）**：各一级模块下的具体功能子模块

---

## 三、各模块职责说明

### 3.1 学生端服务

面向学生用户，提供政策查询、智能问答和个人服务入口。

#### 3.1.1 首页与导航
- **职责**：系统入口页面，提供快捷导航和热点推荐
- **功能点**：
  - 政策热点推荐（当前学期重要通知、截止提醒）
  - 常见问题快捷入口（选课、奖学金、推免等高频问题）
  - 分类浏览导航（按学籍、奖助、竞赛、升学等分类）
  - 搜索框入口（全局问题输入）

#### 3.1.2 智能问答交互
- **职责**：学生与 Agent 进行政策咨询的核心交互界面
- **功能点**：
  - 自然语言问题输入与提交
  - Agent 多轮对话展示
  - 回答内容展示与引用溯源标注
  - 追问与澄清交互
  - 回答反馈（有用/无用）

#### 3.1.3 政策分类查询
- **职责**：按分类维度浏览政策文件和通知
- **功能点**：
  - 学籍与选课政策（选课管理、成绩记载、课程考核）
  - 奖学金与综评（综评办法、奖学金评定、院级奖学金）
  - 转专业与辅修（转专业办法、辅修管理、学分认定）
  - 竞赛与实验室（蓝桥杯等竞赛通知、青禾计划进实验室）
  - 推免与升学（推免方案、推免复试细则）

#### 3.1.4 个人中心
- **职责**：学生个人信息与使用记录管理
- **功能点**：
  - 历史对话记录查看
  - 收藏与书签（重要政策、常用问题）
  - 个人偏好设置（关注年级、关注方向）

---

### 3.2 后台管理端

面向管理员用户，提供知识库维护、元数据管理和数据统计功能。

#### 3.2.1 知识库管理
- **职责**：知识库资料的录入、编辑、审核与发布全流程管理
- **功能点**：
  - 资料列表与检索（按标题、分类、状态筛选）
  - 资料录入与编辑（原始网页、附件、整理稿）
  - 审核与发布管理（草稿、待审核、已发布、已归档状态流转）
  - 分类与标签管理（学校/学院、按主题分类、标签体系）

#### 3.2.2 元数据管理
- **职责**：知识库资料的元信息维护与政策状态标注
- **功能点**：
  - 政策状态标注（当前有效、当前参考、学期有效、历史参考、已废止、待核验）
  - 适用范围设置（适用年级、适用专业、适用对象）
  - 更新时间与核验记录（发布日期、截止日期、最后核验日期）

#### 3.2.3 数据统计看板
- **职责**：系统运行数据与知识库覆盖情况的可视化展示
- **功能点**：
  - 问答量与热门问题统计（日/周/月维度）
  - 知识库覆盖统计（学校资料数、学院资料数、各分类覆盖情况）
  - 用户反馈汇总（回答满意度、未解答问题统计）

#### 3.2.4 用户与权限管理
- **职责**：系统用户账号与操作权限管理
- **功能点**：
  - 管理员账号管理（增删改查）
  - 角色权限分配（超级管理员、知识库编辑、审核员）
  - 操作日志记录

---

### 3.3 Agent 核心服务

系统的智能引擎层，为学生端问答提供后端支撑。

#### 3.3.1 意图识别
- **职责**：理解学生问题的意图，提取关键信息
- **功能点**：
  - 问题分类识别（政策咨询、办事流程、截止时间查询等）
  - 关键实体抽取（专业、年级、奖项名称、课程名称等）
  - 问题难度判断（简单事实型 vs 复杂政策型）

#### 3.3.2 知识检索引擎
- **职责**：从知识库中检索与问题相关的政策资料
- **功能点**：
  - 语义向量检索（基于语义相似度的相关文档召回）
  - 关键词匹配（精确关键词匹配补充）
  - 来源溯源定位（定位到具体文件的具体段落）

#### 3.3.3 回答生成
- **职责**：基于检索到的知识生成结构化回答
- **功能点**：
  - 答案组织与整合（多来源信息整合为连贯回答）
  - 引用标注（标注信息来源文件、发布单位、发布日期）
  - 可信度判断（标注政策状态、适用范围、是否当前有效）

#### 3.3.4 对话管理
- **职责**：维护多轮对话上下文，处理追问和澄清
- **功能点**：
  - 上下文维护（记住前文对话内容）
  - 多轮对话状态管理（会话状态、历史消息）
  - 追问处理（对不明确的问题进行澄清追问）

## 四、模块间关系说明

```
学生端服务 ──→ Agent 核心服务 ──→ 知识库（后台管理端维护）
     ↑                                    ↑
     └──────── 用户交互 ←─────────────────┘
```

1. **学生端服务**是用户直接接触的前端，负责接收学生问题、展示回答。
2. **Agent 核心服务**是后端引擎，接收学生端的问题，进行意图识别、知识检索和回答生成。
3. **后台管理端**负责维护知识库的内容和元数据，为 Agent 核心服务提供高质量的知识来源。
4. Agent 核心服务的检索结果来源于后台管理端维护的知识库。

---

## 五、设计原则

1. **职责分离**：前端交互、后端管理、智能引擎三层分离，便于独立开发和维护。
2. **知识驱动**：以知识库为核心，Agent 能力基于知识库质量，后台管理端重点保障知识准确性。
3. **学生导向**：功能设计围绕学生实际需求（选课、奖助、竞赛、升学），避免冗余功能。
4. **可追溯性**：所有回答均标注来源和政策状态，确保信息可查证、可信赖。
