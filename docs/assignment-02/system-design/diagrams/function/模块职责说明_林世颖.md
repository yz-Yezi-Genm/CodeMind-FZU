**编制人**：林世颖
**日期**：2026-11-09

---

## 一、系统概述

CodeMind-FZU 是**面向福州大学计算机与大数据学院学生的校园事务与发展信息 Agent**，核心目标是为学生提供校园事务与发展相关的智能政策咨询服务。

系统整体采用前后端分离架构，划分为**学生端服务**、**后台管理端**和**Agent 核心服务**三大功能模块，**知识库（数据资源层）**作为独立的数据资源层，为 Agent 提供知识支撑。

---

## 二、功能结构图说明

系统功能结构图采用分层结构：

- **顶层**：面向福州大学计算机与大数据学院学生的校园事务与发展信息 Agent
- **第一层（功能模块）**：学生端服务、Agent 核心服务、后台管理端
- **底层（数据资源层）**：知识库
- **支撑层**：FastAPI / Ask API 接口支撑（学生端与 Agent 核心服务之间的接口支撑，不属于独立一级功能模块）

## 三、各模块职责说明

### 3.1 学生端服务

面向学生用户，提供跨业务场景的通用问答交互和五大业务方向的信息查询。

#### 3.1.1 智能问答交互
- **职责**：跨业务场景共用的问答交互能力
- **功能范围**：
  - 问题输入与提交
  - 必要时补充信息、追问澄清
  - 查看回答依据与来源
  - 对回答进行反馈（有用/无用）

#### 3.1.2 政策与事务办理
- **版本**：v1.0 首版支持
- **职责**：学生日常事务相关的政策咨询与办事指南
- **功能范围**：
  - 奖学金、评优相关政策查询
  - 各类申请条件和办理流程咨询

#### 3.1.3 升学与就业发展
- **版本**：v1.0 首版支持
- **职责**：升学深造与就业发展相关的官方信息查询
- **功能范围**：
  - 升学政策、推免条件查询
  - 学院官方发展信息查询
  - 基于官方政策的通用阶段性准备建议
  - 说明：系统仅解释官方政策、适用范围和条件，不预测个人推免资格，不提供个性化规划

#### 3.1.4 竞赛与科研信息
- **版本**：v1.0 首版支持
- **职责**：学科竞赛与科研项目相关的官方信息查询
- **功能范围**：
  - 竞赛认定规则查询
  - 赛事信息查询
  - 基于官方政策的通用准备建议
  - 说明：系统仅提供已有官方资料支持的信息查询，不提供动态科研机会推荐

#### 3.1.5 学院资源导航
- **版本**：v1.0 首版支持
- **职责**：学院各类资源的导航与查询
- **功能范围**：
  - 实验室、导师方向信息查询
  - 本科生科研资源查询

#### 3.1.6 个人成长档案与长期规划
- **版本**：v2.0 及以后后续迭代
- **职责**：学生个人成长档案与长期发展规划
- **功能范围**：
  - 成长经历记录
  - 阶段目标与个性化发展建议

---

### 3.2 Agent 核心服务

系统的智能引擎层，为学生端问答提供后端支撑。

#### 3.2.1 意图识别与追问澄清
- **职责**：理解学生问题的意图，提取关键信息，必要时追问澄清
- **功能范围**：
  - 问题分类识别
  - 关键实体抽取
  - 必要信息追问与任务澄清

#### 3.2.2 知识检索与证据检查
- **职责**：从知识库中检索与问题相关的政策资料，并进行证据质量检查
- **功能范围**：
  - 语义向量检索
  - 关键词匹配
  - 检索结果证据检查

#### 3.2.3 回答生成与溯源
- **职责**：基于检索到的知识生成结构化回答，确保回答有据可依
- **功能范围**：
  - 答案组织与整合
  - 来源引用与溯源
  - 政策年份、适用对象和有效状态判断
  - 资料不足、冲突或无法确认时的处理

#### 3.2.4 对话管理
- **首版范围**：当前会话上下文维护、追问状态管理
- **后续扩展**：历史对话持久化、跨会话恢复等

---

### 3.3 知识库（数据资源层）

独立的数据资源层，存储系统所需的全部政策资料和元数据。

#### 3.3.1 政策资料存储
- **职责**：存储各类政策文件、办事指南、通知公告等原始资料
- **内容范围**：
  - 学校层面政策文件
  - 学院层面政策文件
  - 各类竞赛、奖学金、推免相关资料

#### 3.3.2 元数据管理
- **职责**：存储资料的元信息和状态标注
- **内容范围**：
  - 政策状态（当前有效、历史参考、已废止）
  - 适用范围（适用年级、专业、对象）
  - 来源信息和更新记录

---

### 3.4 后台管理端

面向管理员用户，负责维护知识库的内容和元数据。

#### 3.4.1 知识库管理
- **首版实现方式**：主要通过脚本和人工审核维护资料
- **职责**：知识库资料的录入、编辑、审核与发布管理
- **功能范围**：
  - 资料录入与编辑（原始网页、附件、整理稿）
  - 审核与发布管理
  - 分类与标签管理
  - 资料来源登记

#### 3.4.2 元数据管理
- **首版实现方式**：主要通过脚本和人工审核维护
- **职责**：知识库资料的元信息维护与政策状态标注
- **功能范围**：
  - 政策状态标注
  - 适用范围设置
  - 有效性核验记录
  - 更新与归档管理

#### 3.4.3 完整后台 Web 界面
- **说明**：后续扩展功能，首版暂不实现完整 Web 界面

## 四、模块间关系说明

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  学生端服务  │────→│ FastAPI/     │────→│ Agent核心服务│
│ （前端交互） │     │ Ask API接口  │     │ （智能引擎） │
└─────────────┘     │ （接口支撑）  │     └──────┬──────┘
                    └──────────────┘            │
                                                ▼
                                        ┌─────────────┐
                                        │ 知识库      │
                                        │（数据资源层）│
                                        └──────┬──────┘
                                               ▲
                                               │
                                        ┌──────┴──────┐
                                        │ 后台管理端   │
                                        │（维护知识库） │
                                        └───────────────┘
```

1. **学生端服务**是用户直接接触的前端，负责接收学生问题、展示回答。
2. **FastAPI / Ask API 接口**作为学生端与 Agent 核心服务之间的接口支撑，负责请求转发和数据格式转换，不属于独立一级功能模块。
3. **Agent 核心服务**是后端引擎，从知识库检索资料，进行意图识别、知识检索和回答生成。
4. **知识库（数据资源层）**是独立的数据资源层，存储政策资料和元数据，为 Agent 提供知识支撑。
5. **后台管理端**负责维护知识库的内容和元数据，确保知识的准确性和时效性。

## 五、设计原则

1. **职责分离**：前端交互、接口支撑、智能引擎、数据资源、后台管理五层分离，便于独立开发和维护。
2. **知识驱动**：以知识库为核心，Agent 能力基于知识库质量，后台管理端重点保障知识准确性和时效性。
3. **分阶段落地**：整体规划五大业务方向，v1.0 优先支持前四个高频场景，个人成长档案与长期规划作为 v2.0 后续迭代。
4. **可追溯、不编造**：有可靠资料依据的回答展示来源，证据不足时明确提示，不编造结论；系统仅解释官方政策，不预测个人情况，不提供个性化规划。
5. **分层扩展**：首版功能优先保障核心问答链路，完整后台 Web 界面等作为后续扩展。
