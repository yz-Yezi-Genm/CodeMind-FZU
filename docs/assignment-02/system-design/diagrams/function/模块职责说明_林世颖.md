## 一、系统概述

CodeMind-FZU 是**面向福州大学计算机与大数据学院学生的校园事务与发展信息 Agent**，核心目标是为学生提供竞赛认定、奖学金申请、保研基本条件、交换与出国信息等校园事务与发展相关的智能政策咨询服务。

系统整体采用前后端分离架构，划分为**学生端服务**、**后台管理端**和**Agent 核心服务**三大功能模块，知识库作为独立的数据资源层，为 Agent 提供知识支撑。

---

## 二、功能结构图说明

系统功能结构图采用三层分解：

- **第一层（顶层）**：面向福州大学计算机与大数据学院学生的校园事务与发展信息 Agent
- **第二层（一级模块）**：学生端服务、后台管理端、Agent 核心服务
- **第三层（二级子模块）**：各一级模块下的具体功能子模块

## 三、各模块职责说明

### 3.1 学生端服务

面向学生用户，提供政策咨询交互和四大场景入口。

#### 3.1.1 政策问答交互
- **职责**：学生与 Agent 进行政策咨询的核心交互界面
- **功能点**：
  - 自然语言问题输入与提交
  - Agent 多轮对话展示
  - 回答内容展示与引用溯源标注
  - 追问与澄清交互
  - 回答反馈（有用/无用）

#### 3.1.2 四大场景咨询
- **职责**：首版重点服务的四个高频场景入口
- **功能点**：
  - 竞赛认定咨询（蓝桥杯、创新创业学分等）
  - 奖学金申请咨询（综评、校奖、院级奖学金等）
  - 保研基本条件咨询（推免资格、复试要求等）
  - 交换与出国信息咨询（交换项目、出国交流等）

#### 3.1.3 首页与导航
- **职责**：系统入口页面，提供快捷导航和热点推荐
- **功能点**：
  - 四大场景快捷入口
  - 当前学期重要通知、截止提醒
  - 常见问题推荐
  - 搜索框入口（全局问题输入）

#### 3.1.4 个人中心
- **职责**：学生个人信息与使用记录管理
- **功能点**：
  - 历史对话记录查看
  - 收藏与书签（重要政策、常用问题）
  - 个人偏好设置（关注年级、关注方向）

---

### 3.2 后台管理端

面向管理员用户，提供知识库维护和元数据管理功能。

#### 3.2.1 知识库管理
- **职责**：知识库资料的录入、编辑、审核与发布全流程管理
- **功能点**：
  - 资料列表与检索（按标题、分类、状态筛选）
  - 资料录入与编辑（原始网页、附件、整理稿）
  - 审核与发布管理（草稿、待审核、已发布、已归档状态流转）
  - 分类与标签管理（学校/学院、按主题分类、标签体系）
  - **资料来源登记**（记录官方来源网址、发布单位、原始文件路径）

#### 3.2.2 元数据管理
- **职责**：知识库资料的元信息维护与政策状态标注
- **功能点**：
  - 政策状态标注（当前有效、当前参考、学期有效、历史参考、已废止、待核验）
  - 适用范围设置（适用年级、适用专业、适用对象）
  - **有效性核验记录**（发布日期、截止日期、最后核验日期）
  - **更新与归档管理**（版本更新记录、旧版本归档、废止资料标记）

#### 3.2.3 数据统计看板
- **职责**：系统运行数据与知识库覆盖情况的可视化展示
- **功能点**：
  - 问答量与热门问题统计（日/周/月维度）
  - 知识库覆盖统计（学校资料数、学院资料数、各分类覆盖情况）
  - 用户反馈汇总（回答满意度、未解答问题统计）

#### 3.2.4 用户与权限管理
- **职责**：系统用户账号与操作权限管理
- **功能点**：
  - 管理员账号管理（增删改查）
  - 角色权限分配（超级管理员、知识库编辑、审核员）
  - 操作日志记录

---

### 3.3 Agent 核心服务

系统的智能引擎层，为学生端问答提供后端支撑。

#### 3.3.1 意图识别与追问澄清
- **职责**：理解学生问题的意图，提取关键信息，必要时追问澄清
- **功能点**：
  - 问题分类识别（竞赛认定、奖学金、保研、交换出国等）
  - 关键实体抽取（专业、年级、奖项名称、课程名称等）
  - **必要信息追问与任务澄清**（问题不明确时主动追问，确认年级、专业等关键信息）

#### 3.3.2 知识检索与证据检查
- **职责**：从知识库中检索与问题相关的政策资料，并进行证据质量检查
- **功能点**：
  - 语义向量检索（基于语义相似度的相关文档召回）
  - 关键词匹配（精确关键词匹配补充）
  - **检索结果证据检查**（检查资料是否官方来源、是否为最新版本、是否适用对应年级）

#### 3.3.3 回答生成与溯源
- **职责**：基于检索到的知识生成结构化回答，确保回答有据可依
- **功能点**：
  - 答案组织与整合（多来源信息整合为连贯回答）
  - **来源引用与溯源**（标注信息来源文件、发布单位、发布日期）
  - **政策年份、适用对象和有效状态判断**（明确标注政策是否当前有效、适用年级和对象）
  - **资料不足、冲突或无法确认时的处理**（明确告知用户"当前资料不足，无法确认"，不编造结论）

#### 3.3.4 对话管理
- **职责**：维护多轮对话上下文，处理追问和澄清
- **功能点**：
  - 上下文维护（记住前文对话内容）
  - 多轮对话状态管理（会话状态、历史消息）
  - 追问处理（对不明确的问题进行澄清追问）

## 四、模块间关系说明

```
学生端服务 ──→ 后端接口 ──→ Agent 核心服务 ──→ 知识库（独立数据资源层）
     ↑                                    ↑                ↑
     │                                    │                │
     └──────── 用户交互 ←─────────────────┘                │
                                                           │
后台管理端 ────────────────────────────────────────────────┘
（维护知识库内容与元数据）
```

1. **学生端服务**是用户直接接触的前端，负责接收学生问题、展示回答。
2. **后端接口**负责学生端与 Agent 核心服务之间的请求转发和数据格式转换。
3. **Agent 核心服务**是后端引擎，接收学生端的问题，进行意图识别、知识检索和回答生成。
4. **知识库**是独立的数据资源层，存储政策资料和元数据，为 Agent 提供知识支撑。
5. **后台管理端**负责维护知识库的内容和元数据，确保知识的准确性和时效性。

---

## 五、设计原则

1. **职责分离**：前端交互、后端管理、智能引擎、知识库数据四层分离，便于独立开发和维护。
2. **知识驱动**：以知识库为核心，Agent 能力基于知识库质量，后台管理端重点保障知识准确性和时效性。
3. **首版聚焦**：首版聚焦竞赛认定、奖学金申请、保研基本条件、交换与出国信息四个高频场景，避免功能冗余。
4. **可追溯、不编造**：有可靠资料依据的回答展示来源，证据不足时明确提示，不编造结论。
5. **分层扩展**：首版功能优先保障核心问答链路，个人中心、数据统计、复杂权限管理等作为后续扩展。
