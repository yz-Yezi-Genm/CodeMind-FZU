# CodeMind-FZU 系统功能结构图说明

**编制人**：林世颖
**日期**：2026-11-08

---

## 一、系统概述

CodeMind-FZU 是**面向福州大学计算机与大数据学院学生的校园事务与发展信息 Agent**，核心目标是为学生提供校园事务与发展相关的智能政策咨询服务。

系统整体采用前后端分离架构，划分为**学生端服务**、**后台管理端**和**Agent 核心服务**三大功能模块，知识库作为独立的数据资源层，为 Agent 提供知识支撑。

---

## 二、功能结构图说明

系统功能结构图采用三层分解：

- **第一层（顶层）**：面向福州大学计算机与大数据学院学生的校园事务与发展信息 Agent
- **第二层（一级模块）**：学生端服务、后台管理端、Agent 核心服务
- **第三层（二级子模块）**：各一级模块下的具体功能子模块

---

## 三、各模块职责说明

### 3.1 学生端服务

面向学生用户，提供五大业务方向的信息查询与智能问答服务。

#### 3.1.1 政策与事务办理
- **职责**：学生日常事务相关的政策咨询与办事指南
- **功能点**：
  - 学籍与选课政策咨询
  - 奖学金与综评政策咨询
  - 转专业与辅修政策咨询
  - 考试与成绩相关政策咨询

#### 3.1.2 升学与就业发展
- **职责**：升学深造与就业发展相关的信息查询
- **功能点**：
  - 保研与推免政策咨询
  - 交换与出国交流信息
  - 就业与职业发展指导

#### 3.1.3 学院资源导航
- **职责**：学院各类资源的导航与查询
- **功能点**：
  - 学院实验室与导师信息
  - 学院教务与学生工作通知
  - 学院各类办事指南

#### 3.1.4 竞赛与科研信息
- **职责**：学科竞赛与科研项目相关的信息咨询
- **功能点**：
  - 学科竞赛信息咨询（蓝桥杯等）
  - 创新创业学分认定
  - 科研项目与实验室招募信息

#### 3.1.5 个人成长档案与长期规划
- **职责**：学生个人成长档案与长期发展规划
- **功能点**：
  - 个人学习档案记录
  - 发展规划与目标管理
  - 长期发展路径推荐

---

### 3.2 后台管理端

面向管理员用户，提供知识库维护与元数据管理功能。

#### 3.2.1 知识库管理
- **职责**：知识库资料的录入、编辑、审核与发布管理
- **首版实现方式**：主要通过脚本和人工审核维护资料
- **功能点**：
  - 资料录入与编辑（原始网页、附件、整理稿）
  - 审核与发布管理
  - 分类与标签管理
  - 资料来源登记

#### 3.2.2 元数据管理
- **职责**：知识库资料的元信息维护与政策状态标注
- **首版实现方式**：主要通过脚本和人工审核维护
- **功能点**：
  - 政策状态标注
  - 适用范围设置
  - 有效性核验记录
  - 更新与归档管理

#### 3.2.3 完整后台 Web 界面
- **职责**：完整的可视化后台管理系统
- **说明**：属于后续扩展功能，首版暂不实现完整 Web 界面

---

### 3.3 Agent 核心服务

系统的智能引擎层，为学生端问答提供后端支撑。

#### 3.3.1 意图识别与追问澄清
- **职责**：理解学生问题的意图，提取关键信息，必要时追问澄清
- **功能点**：
  - 问题分类识别
  - 关键实体抽取
  - 必要信息追问与任务澄清

#### 3.3.2 知识检索与证据检查
- **职责**：从知识库中检索与问题相关的政策资料，并进行证据质量检查
- **功能点**：
  - 语义向量检索
  - 关键词匹配
  - 检索结果证据检查

#### 3.3.3 回答生成与溯源
- **职责**：基于检索到的知识生成结构化回答，确保回答有据可依
- **功能点**：
  - 答案组织与整合
  - 来源引用与溯源
  - 政策年份、适用对象和有效状态判断
  - 资料不足、冲突或无法确认时的处理

#### 3.3.4 对话管理
- **职责**：维护多轮对话上下文，处理追问和澄清
- **首版范围**：当前会话上下文维护、追问状态管理
- **后续扩展**：历史对话持久化、跨会话恢复等

## 四、模块间关系说明

```
学生端服务 ──→ 后端接口 ──→ Agent 核心服务 ──→ 知识库（独立数据资源层）
     ↑                                    ↑                ↑
     │                                    │                │
     └──────── 用户交互 ←─────────────────┘                │
                                                           │
后台管理端 ────────────────────────────────────────────────┘
（维护知识库内容与元数据）
```

1. **学生端服务**是用户直接接触的前端，负责接收学生问题、展示回答。
2. **后端接口**负责学生端与 Agent 核心服务之间的请求转发和数据格式转换。
3. **Agent 核心服务**是后端引擎，接收学生端的问题，进行意图识别、知识检索和回答生成。
4. **知识库**是独立的数据资源层，存储政策资料和元数据，为 Agent 提供知识支撑。
5. **后台管理端**负责维护知识库的内容和元数据，确保知识的准确性和时效性。

---

## 五、设计原则

1. **职责分离**：前端交互、后端管理、智能引擎、知识库数据四层分离，便于独立开发和维护。
2. **知识驱动**：以知识库为核心，Agent 能力基于知识库质量，后台管理端重点保障知识准确性和时效性。
3. **首版聚焦**：首版聚焦政策与事务办理、升学与就业发展、学院资源导航、竞赛与科研信息四个高频场景。
4. **可追溯、不编造**：有可靠资料依据的回答展示来源，证据不足时明确提示，不编造结论。
5. **分层扩展**：首版功能优先保障核心问答链路，个人成长档案、完整后台 Web 界面等作为后续扩展。
