# CodeMind-FZU 知识库设计方案

## 一、知识库建设目标

本知识库面向福州大学计算机与大数据学院（软件学院）本科生，重点服务大一至大三学生，为学生提供选课、考试、学分、综合素质评价、奖学金、转专业、辅修、竞赛、实验室和升学准备等事项的政策查询与办事参考。

知识库回答政策问题时，应优先给出适用对象、政策状态、办理时间和官方来源；对于已经过期的年度通知，应明确标注为流程参考，不能当作当前开放事项。

## 二、知识库范围

### 1. 核心范围

- 学校本科生学生管理规定；
- 综合素质评价和奖学金政策；
- 选课、补考、重修、缓考和成绩记载；
- 转专业、辅修专业、课程替代和学分认定；
- 学士学位、毕业要求和学术诚信；
- 创新创业实践与素质拓展学分；
- 计算机学院奖学金、竞赛、实验室和推免相关通知；
- 面向大一至大三学生的学期通知、报名通知和办事指南。

### 2. 暂不作为核心范围的内容

- 纯教师培训、教师职称和学校内部行政通知；
- 与本科生学习和发展无关的新闻资讯；
- 只面向研究生的招生、培养和奖助政策；
- 个人隐私、成绩、学号、身份证件和登录凭据；
- 未经官方来源核实的网络文章、个人经验和聊天记录。

## 三、信息来源

### 1. 一级来源：学校官方文件

- 福州大学教务处：`https://jwch.fzu.edu.cn/`
- 福州大学学生工作部（处）及学生工作信息平台：`https://stuic.fzu.edu.cn/`
- 福州大学教学文件、学生手册和办事指南栏目；
- 福州大学正式发布的校级文件、通知、办法、细则及附件。

### 2. 二级来源：学院官方信息

- 福州大学计算机与大数据学院（软件学院）官网：`https://ccds.fzu.edu.cn/`
- 学院教务、学生工作、竞赛、实验室、奖学金和推免栏目；
- 学院正式发布的通知、评选办法、报名表和需求表。

### 3. 来源使用原则

- 政策结论必须能追溯到官方网页或官方附件；
- 同一事项存在多个版本时，以最新且适用于对应年级的文件为准；
- 原始网页、附件和中文整理稿同时保留；
- 只有标题没有取得正文的页面，不直接作为正式政策依据；
- 发现网页需要统一身份认证时，先记录为“待补充”并告知用户具体网址和原因；用户可自行在浏览器中完成登录，不能向助手提供账号、密码或验证码。用户确认登录完成后，再继续整理授权范围内的页面；不保存个人信息、登录信息或与知识库无关的页面内容。

## 四、数据分类

### 1. 按发布主体分类

| 类别 | 内容 | 保存位置 |
|---|---|---|
| 学校政策 | 学生管理、综评、奖学金、学位、转专业等 | `原始资料/学校`、`整理资料/学校` |
| 教务处通知 | 选课、考试、重修、辅修、学籍和课程通知 | `原始资料/学校`、`整理资料/学校` |
| 学院通知 | 院级奖学金、竞赛、青禾计划、推免等 | `原始资料/学院`、`整理资料/学院` |

### 2. 按资料性质分类

- **规范性文件**：办法、细则、规定、管理实施办法；
- **学期通知**：选课、考试、重修、课程学习等有明确时间窗口的通知；
- **年度通知**：奖学金、竞赛、实验室、招生或推免等年度事项；
- **办事指南**：办理材料、办理部门、办理流程和办理时间；
- **附件资料**：PDF、Word、Excel、PPT、RAR等官方附件；
- **历史版本**：已废止、被替代或只适用于旧年级的文件。

### 3. 按政策状态分类

- 当前有效；
- 当前参考；
- 本学期或本年度有效；
- 截止后流程参考；
- 部分年级适用；
- 已废止或历史参考；
- 待核验或待补充。

### 4. 每条资料保存的元数据

记录编号、标题、发布单位、负责部门、文号、资料类型、发布日期、生效日期、适用年级、适用专业、适用对象、政策状态、来源网址、原始文件路径、附件路径、截止日期、文件成文日期、最后核验日期和内容哈希。

## 五、资料存储结构

```text
知识库/政策资料/
├─ 原始资料/
│  ├─ 学校/       官网HTML和学校附件
│  └─ 学院/       学院官网HTML和学院附件
├─ 整理资料/
│  ├─ 学校/       中文Markdown整理稿
│  └─ 学院/       中文Markdown整理稿
├─ 采集记录/      每次扫描、发现和收录日志
├─ 知识库索引.csv  结构化元数据索引
└─ 整理资料/
   ├─ 知识库资料完整清单.md
   └─ 知识库设计方案.md
```

## 六、更新方式

### 1. 更新频率

- 学校和学院官网通知：每周检查一次，开学、选课、评奖和考试季增加检查频率；
- 规范性文件：每月检查一次，发现新版本立即核验；
- 年度通知：每年重新查找，旧通知保留并标记历史状态；
- 学期通知：保存截止日期，事项结束后改为“流程参考”；
- 重要政策变更：发现后在24小时内补充索引并记录核验日期。

### 2. 更新流程

1. 从官方首页或栏目页按发布日期从新到旧扫描；
2. 筛选与大一至大三本科生有关的资料；
3. 下载原始网页和官方附件；
4. 提取正文，整理为中文Markdown；
5. 添加适用对象、发布日期、截止日期和政策状态；
6. 计算内容哈希，避免重复收录；
7. 同步更新 `知识库索引.csv`、`知识库资料完整清单.md` 和本设计方案中的统计；
8. 对旧版本进行状态变更，不直接删除原文件；
9. 进行抽查，确认整理稿与官方原文一致。

### 3. 版本处理规则

- 新版本替代旧版本时，旧版本保留为历史资料；
- 同一政策适用于不同年级时，分别记录适用年级；
- 年度活动通知不覆盖上一年度通知；
- 网页发布时间、文件落款日期和生效日期分别记录；
- 不能确定是否仍有效的资料标记“待核验”，不直接回答为当前政策。

## 七、当前建设情况

截至2026年10月21日，知识库已有31条记录，其中学校和教务处资料26条，计算机学院资料5条。当前最需要补充的是计算机学院综测加分细则、各专业培养方案、本科生推免资格推荐办法和创新创业学分认定项目目录。
